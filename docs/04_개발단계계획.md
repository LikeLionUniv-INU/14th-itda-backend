# 잇다(ITDA) 백엔드 개발 단계 계획서

> **버전**: v1.0  
> **작성일**: 2026-08-12  
> **목적**: AI 또는 개발자가 이 문서만 따라가면 순서대로 구현 가능하도록, 단계별 작업 내용/산출물/검증 기준을 명확히 정의

---

## 개발 원칙

1. **반드시 이 순서대로 진행한다** — 각 단계는 이전 단계의 산출물에 의존한다
2. **단계 완료 기준을 모두 충족해야 다음 단계로 넘어간다**
3. **각 단계 완료 후 curl 테스트로 API 명세 기준 검증한다** (해당 시)
4. **개발 완료 후 개발 문서를 반드시 작성한다** (`docs/dev/` 하위에)

## Phase 2: 인증 (Auth)

### 작업 내용

#### 2-1. User 엔티티
- [ ] `User` 엔티티 (`domain/user/entity/`)
  - id, email, password, firstName, lastName, country, language
  - `BaseTimeEntity` 상속
- [ ] `UserRepository` (JpaRepository)

#### 2-2. 회원가입 API
- [ ] `POST /api/auth/signup`
- [ ] `SignupRequest` DTO + Bean Validation
  - firstName: `@NotBlank`, 영문자만 (`@Pattern`)
  - lastName: `@NotBlank`, 영문자만
  - email: `@NotBlank`, `@Email`
  - password: 8~16자 영문+숫자 (`@Pattern`)
  - country: `@NotBlank`
  - language: `@NotBlank`
- [ ] `SignupResponse` DTO
- [ ] `AuthService.signup()` — 비밀번호 BCrypt 해싱, 이메일 중복 검사
- [ ] `AuthController`

#### 2-3. JWT 토큰 발급 유틸
- [ ] `JwtTokenProvider` (`global/security/`)
  - Access Token 생성 (15분, userId/email/role 포함 불가 — role은 팀별이므로 userId만)
  - Refresh Token 생성 (7일)
  - 토큰 검증 및 파싱
- [ ] `RefreshToken` 엔티티 + Repository

#### 2-4. 로그인 API
- [ ] `POST /api/auth/login`
- [ ] `LoginRequest` DTO
- [ ] `LoginResponse` DTO (accessToken, refreshToken, tokenType, expiresIn)
- [ ] `AuthService.login()` — 이메일로 사용자 조회 → 비밀번호 검증 → 토큰 발급

#### 2-5. 토큰 갱신 API
- [ ] `POST /api/auth/refresh`
- [ ] Refresh Token 유효성 검증 → 새 Access/Refresh Token 발급
- [ ] 기존 Refresh Token 삭제 (Rotation)

#### 2-6. Spring Security 설정
- [ ] `SecurityConfig` (`global/config/`)
  - `/api/auth/signup`, `/api/auth/login`, `/api/auth/refresh` → permitAll
  - `/swagger-ui/**`, `/v3/api-docs/**` → permitAll
  - 나머지 → authenticated
  - CSRF 비활성화 (REST API)
  - 세션 STATELESS
- [ ] `JwtAuthenticationFilter` (OncePerRequestFilter)
  - Authorization 헤더에서 Bearer 토큰 추출
  - 토큰 검증 → SecurityContext에 인증 정보 설정
- [ ] `PasswordEncoder` Bean (BCryptPasswordEncoder)

### 완료 기준
- [ ] curl 테스트 — 회원가입 → 로그인 → 토큰 발급 → 보호된 API 접근 → 토큰 갱신
- [ ] 유효성 검사 실패 시 `{ success: false, message: "...", data: null }` 확인
- [ ] 이메일 중복 시 409 응답 확인
- [ ] 잘못된/만료된 토큰으로 접근 시 401 응답 확인
- [ ] 개발 문서 작성: `docs/dev/phase2_인증.md`

### curl 테스트 시나리오
```bash
# 1. 회원가입
curl -X POST http://localhost:8080/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Seoyeon","lastName":"Kim","email":"test@test.com","password":"testpass1","country":"South Korea","language":"ko"}'

# 2. 이메일 중복 회원가입 → 409
curl -X POST http://localhost:8080/api/auth/signup \
  -H "Content-Type: application/json" \
  -d '{"firstName":"Test","lastName":"User","email":"test@test.com","password":"testpass1","country":"Japan","language":"ja"}'

# 3. 로그인
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"testpass1"}'

# 4. 잘못된 비밀번호 → 401
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@test.com","password":"wrongpass1"}'

# 5. 보호된 API 접근 (토큰 필요)
curl -X GET http://localhost:8080/api/users/me \
  -H "Authorization: Bearer {accessToken}"

# 6. 토큰 갱신
curl -X POST http://localhost:8080/api/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken":"{refreshToken}"}'
```
