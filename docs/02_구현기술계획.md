## 2. 기술 선정 근거

### 2.1 Language & Framework: Java 21 + Spring Boot 3.3+

#### 왜 Java 21 LTS인가?
- **Virtual Threads (Project Loom)**: 경량 스레드로 I/O 대기 작업(AI 번역 API 호출 등)의 동시성 대폭 향상. Reactive 없이도 높은 처리량 확보
- **Record**: 불변 DTO를 간결하게 정의 (API 요청/응답 객체에 활용)
- **Pattern Matching**: switch 표현식, instanceof 패턴 매칭으로 코드 가독성 향상
- **Sealed Classes**: 문서 상태(작성중/완료/번역중 등) 열거에 활용
- **Sequenced Collections**: 순서 보장 컬렉션 API 개선
- **LTS 지원**: 장기 지원 버전으로 안정적인 운영 환경 보장

#### 왜 Spring Boot 3.3+인가?
- **프레임워크 비교 검토 결과**:

| 항목 | Spring Boot 3.3 | NestJS 10.x | FastAPI 0.115.x |
|------|----------------|-------------|-----------------|
| 생태계 성숙도 | 최상 | 상 | 중 |
| JWT/RBAC | Spring Security (최상) | Passport.js (상) | python-jose (중) |
| 파일 업로드 | 내장 (MultipartFile) | Multer | python-multipart |
| 실시간 (SSE) | SseEmitter 내장 | 가능 | sse-starlette |
| ORM/DB 생태계 | JPA/Hibernate (최상) | TypeORM/Prisma (상) | SQLAlchemy (상) |
| 한국 개발자 풀 | 가장 넓음 | 넓음 | 보통 |
| 안정성 (Stable) | GA | GA | 아직 1.0 미출시 |

- **결론**: JWT 인증, 역할 기반 접근제어(팀장/팀원), 파일 업로드, SSE 실시간 통신 등 모든 요구사항에 대해 **Spring Boot가 가장 성숟한 first-party 솔루션**을 보유
- **Java 21 Virtual Threads**: 기존 스레드 풀 대비 경량 스레드로 동시 처리 성능 향상. AI 번역 API 호출 등 I/O 대기 작업에 효과적. Reactive(WebFlux) 없이도 높은 동시성 확보

### 2.2 Database: PostgreSQL 17+

#### 왜 PostgreSQL인가?

| 항목 | PostgreSQL 17 | MySQL 8.4 LTS | MongoDB 7.x |
|------|-------------|--------------|-------------|
| 복잡한 관계형 스키마 | 최상 | 상 | 부적합 |
| JSONB 지원 | 네이티브 | JSON 지원 (약함) | 네이티브 |
| 버전 관리 패턴 | Temporal 쿼리 용이 | 가능 | 가능 |
| 한국어 전문검색 | pg_trgm, 형태소 | 제한적 | 가능 |
| 트랜잭션 안정성 | MVCC (최상) | InnoDB (상) | 4.0+ (개선 중) |

- **데이터 특성 분석**: 사용자 → 팀프로젝트 → 문서 → 페이지 → 핀(좌표) → 요구사항(5개 탭)이라는 **깊은 관계형 구조**. MongoDB는 이 구조에 부적합
- **PostgreSQL 17 주요 기능**:
  - **Incremental Backup**: 대규모 데이터 백업 효율화
  - **JSON_TABLE 개선**: 번역 결과 등 JSON 데이터 처리에 유리
  - **MERGE 명령어 개선**: 문서 버전 업데이트 시 upsert 패턴에 활용
  - **Vacuum/메모리 관리 개선**: 문서 수정이 빈번한 서비스에 안정적

#### Redis 7.4+ — 캐시 & 실시간

- **번역 진행 상태 관리**: 언어별 번역 상태(대기/진행/완료)를 Redis에 저장하고 SSE로 클라이언트에 push
- **세션/토큰 관리**: Refresh Token 블랙리스트, 로그인 세션 관리
- **Pub/Sub**: 번역 완료 이벤트 브로드캐스팅

### 2.3 ORM & Migration: JPA/Hibernate 6.5+ & Flyway 10.x

#### JPA/Hibernate 6.5+
- Spring Boot 3.3 기본 ORM
- **Jakarta EE 10** 네임스페이스 전환 완료
- **SoftDelete 어노테이션**: 문서/버전 소프트 삭제에 유용
- **Java Record 활용**: DTO를 Record로 간결하게 정의
- **타입 안전성 향상**: Criteria API 개선

#### Flyway 10.x
- **SQL 기반 마이그레이션**: 버전 관리 및 롤백 용이
- **Spring Boot 자동 연동**: `spring.flyway.*` 설정만으로 마이그레이션 자동 실행
- **팀 협업**: 각 개발자가 V1, V2, ... 순서대로 마이그레이션 파일 추가하여 충돌 방지

#### HikariCP 5.1+
- Spring Boot 3.x 기본 커넥션 풀
- JVM 최고 성능의 커넥션 풀
- 별도 설정 불필요 (Spring Boot 기본 내장)

### 2.4 AI 번역: OpenAI GPT API (1순위) + Google Cloud Translation (보조)

#### API 비교 검토

| 항목 | OpenAI GPT-4o | Google Cloud Translation v3 | DeepL | Claude API | Papago |
|------|-------------|---------------------------|-------|-----------|--------|
| 한국어↔영어 품질 | 최상 | 상 | 상 | 최상 | 상 |
| 한국어↔일본어 | 최상 | 상 | 상 | 상 | 상 |
| 한국어↔중국어 | 최상 | 상 | 상 | 상 | 상 |
| 한국어↔베트남어 | 상 | 상 | **미지원** | 상 | 상 |
| 기술문서 문맥 이해 | 최상 | 중 | 중 | 최상 | 하 |
| 용어집(Glossary) | 시스템 프롬프트 | 네이티브 지원 | 지원 | 시스템 프롬프트 | 미지원 |
| 가격 (1M 토큰/문자) | ~$2.5/$10 | $20/1M 문자 | $25/1M 문자 | ~$3/$15 | $20/1M 문자 |
| Batch API | 50% 할인 (24h) | 지원 (GCS) | 미지원 | 50% 할인 | 미지원 |
| 5개 언어 전체 지원 | O | O | **X (베트남어 미지원)** | O | O |

#### 선정: OpenAI GPT API (1순위)

- **문맥 인식 번역**: 요구사항 명세서의 기술 용어를 정확하게 번역 (시스템 프롬프트로 용어집 정의 가능)
- **구조 보존**: JSON 포맷으로 번역 요청 → 필드명 보존한 채 내용만 번역
- **5개 언어 모두 지원**: 한국어/영어/일본어/중국어(간체)/베트남어
- **Batch API**: 대량 번역 시 50% 비용 절감 (24시간 이내 처리)
- **DeepL 탈락 사유**: 베트남어 미지원으로 우리 서비스 요구사항에 부적합

#### 보조: Google Cloud Translation v3
- 단순 UI 텍스트나 짧은 문구 번역에는 Google Translation이 비용 효율적
- OpenAI API 장애 시 **fallback** 용도

#### 번역 파이프라인 아키텍처

```
[문서 작성 완료]
      │
      ▼
[번역 Job 생성] → Redis에 상태 저장 (jobId, 언어별 상태: PENDING)
      │
      ▼
[번역 Worker] → 언어별 순차/병렬 처리
      │          ├─ 한국어: COMPLETED (원본 유지)
      │          ├─ 영어:   PENDING → TRANSLATING → COMPLETED
      │          ├─ 일본어: PENDING → TRANSLATING → COMPLETED
      │          └─ ...
      │
      ▼ (각 언어 완료 시)
[Redis 상태 업데이트] → SSE로 클라이언트에 진행률 push
      │
      ▼ (전체 완료)
[번역된 문서를 DB에 저장] → 팀프로젝트 내 문서로 등록
      │
      ▼
[클라이언트: "전체 번역 완료" 3초 노출 → 팀프로젝트 메인 이동]
```

#### 진행률 계산 방식
- 실시간 percentage가 어렵다면 → **1/n 방식** 채택
- n = 번역 대상 언어 수, 각 언어 번역 완료 시 `완료수/n * 100`%
- 예: 3개 언어 중 1개 완료 → 33%, 2개 완료 → 66%, 3개 완료 → 100%

#### 캐싱 전략
- 번역 결과를 **소스 텍스트 해시 + 대상 언어**를 키로 캐싱
- 문서 수정 시 **변경된 요구사항만 재번역** (전체 재번역 방지)

### 2.5 인증: JWT (Access + Refresh Token)

#### 구현 방식
- **Spring Security 6.3+**의 `OAuth2 Resource Server` 모듈 활용
- 토큰 생성은 **jjwt 0.12.6** 라이브러리 사용 (커스텀 토큰 발급 필요)

#### 토큰 전략

| 항목 | Access Token | Refresh Token |
|------|-------------|---------------|
| 유효기간 | 15분 | 7일 |
| 저장 위치 | 클라이언트 (Authorization Header) | HttpOnly Cookie 또는 DB |
| 포함 정보 | userId, email, role | userId |
| 갱신 방식 | Refresh Token으로 재발급 | 로그인 시 재발급 |

#### 역할 기반 접근 제어 (RBAC)

```
비로그인 → 회원가입, 로그인만 가능
로그인 사용자 → 메인 대시보드, 팀 생성/참여
팀장 (TEAM_LEADER) → 문서 생성, 문서 작성, 문서 수정, 버전 삭제
팀원 (TEAM_MEMBER) → 문서 확인 (읽기 전용)
```

### 2.7 실시간 통신: SSE (Server-Sent Events)

#### 왜 SSE인가?

| 항목 | SSE | WebSocket |
|------|-----|-----------|
| 방향 | 단방향 (서버→클라이언트) | 양방향 |
| 복잡도 | 낮음 | 높음 |
| HTTP 호환 | HTTP/1.1, HTTP/2 네이티브 | 별도 프로토콜 (ws://) |
| 프록시/LB 통과 | 쉬움 | 설정 필요 |
| 자동 재연결 | 브라우저 내장 | 직접 구현 |
| 우리 용도 (번역 진행률) | **적합** | 오버 스펙 |

- 번역 진행 상태는 **서버 → 클라이언트 단방향** 통신이므로 SSE가 최적
- Spring Boot의 `SseEmitter` 사용하여 간단하게 구현 가능

#### 구현 패턴
```java
@GetMapping(value = "/api/translations/{jobId}/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter streamTranslationProgress(@PathVariable String jobId) {
    SseEmitter emitter = new SseEmitter(300_000L); // 5분 타임아웃
    // Redis Pub/Sub로 진행률 변경 감지 → emitter.send()
    return emitter;
}
```

### 2.10 배포 & CI/CD

#### 환경 구성

| 환경 | 구성 |
|------|------|
| **로컬 개발** | Docker Compose (Spring Boot + PostgreSQL + Redis + MinIO) |

| **운영 배포** | AWS EC2 또는 Railway/Render (팀 규모에 맞게 선택) |

#### Docker Compose 구성 (로컬 개발)
```yaml
services:
  app:        # Spring Boot 애플리케이션
  postgres:   # PostgreSQL 17
  redis:      # Redis 7.4
  minio:      # MinIO (S3 호환 로컬 스토리지)
```

#### GitHub Actions CI 파이프라인
```
Push/PR → Checkout → Setup JDK 21 → Gradle Build → Test (Testcontainers)
  → Docker Build → (운영 배포 시) Push to Registry → Deploy
```

#### Nginx 1.27+
- 리버스 프록시: HTTPS 종단, 요청 라우팅
- SSL: Let's Encrypt + Certbot 자동 갱신
- SSE 프록시 설정: `proxy_buffering off` 필수
